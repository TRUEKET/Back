# 실제 HTTP 연동 검증 (#70)

2026-11-16, develop 기반. Postman을 대신해 HTTP 클라이언트가 실행 중인 Spring 서버에 실제 요청을 보냈다. MockMvc·H2 검증과 별개이며 DB는 팀 Supabase, AI는 설정된 OpenAI, 사진은 실제 Private `report-evidence` Storage를 사용했다.

## 환경과 범위

- 서버는 로컬 127.0.0.1:18091로 한정했다. 기존 IntelliJ 서버는 종료하지 않았다.
- 기존 로컬 환경변수를 메모리로 전달하고 키·비밀번호·쿠키·CSRF 토큰은 이 문서에 기록하지 않았다.
- 스키마는 validate로 기동했다. 공유 DB 스키마를 수정하지 않았다.
- 테스트마다 새 가상 이메일·번호로 계정을 만들었다. 캡처·송금 완료 사진은 가상 계좌를 그린 합성 이미지다. 실제 송금은 하지 않았다.
- SMS는 demo 수신함이며 실제 휴대폰 소유 확인은 아니다. AI와 Storage는 실제 호출했다.
- SMTP와 스케줄러는 임시 실행기에서 비활성화했다. 다른 사용자의 메일·사진·기간 만료 작업은 실행하지 않았다.
- 배포·트루샷 AI/CV·이의제기 메일 발송·모든 실사용 사진의 인식률은 범위에 포함하지 않는다.

## 이번 실호출에서 발견하고 수정한 누락

최초 실행에서는 판독부터 FRAUD 등록·조회까지 성공했지만, 탈퇴 후 소비된 `pending_report_evidence` 행이 1건 남았다. 기존 WithdrawalRepository가 정식 evidence만 수집·삭제하고 임시 증빙 테이블을 포함하지 않았기 때문이다.

- 탈퇴 시 소비 여부와 무관하게 본인의 임시 증빙 파일 키를 잠금 조회해 Storage 삭제 대상으로 수집한다.
- 다른 사용자 임시 증빙에서 같은 파일을 참조하면 삭제하지 않고 충돌 처리한다.
- Storage 삭제 성공 후 본인의 임시 증빙 메타데이터도 같은 DB 트랜잭션에서 제거한다.
- 삭제 실패 시 계정·토큰을 보존하고 재시도한다.

첫 실행의 남은 메타데이터는 그 실행에서 생성한 정확한 사용자·토큰·판독 ID로만 정리했다. 수정 후에는 새 계정으로 전체 흐름을 다시 실행하고, 소비된 증빙과 미등록 임시 증빙이 모두 API 탈퇴로 정리되는 것을 확인했다. 이번 실행의 합성 피드백 행도 해당 판독 ID에 한정해 정리했다. 공유 식별자는 보존했다.

자동 회귀 검사도 **390개 통과, 실패·오류·제외 0**이다. 신규 3개 검사는 임시 증빙 삭제·타인 보존, Storage 실패 후 재시도, 타인 임시 파일 참조 충돌을 다룬다. 자동 검사에서는 외부 Storage를 대체하며 위 실제 파일 검증과 구분한다.

## 해석의 한계

이는 합성 대화·송금 사진 한 종류와 해당 계정 흐름의 성공 확인이다. 외부 AI 호출 시간·정확도·모든 운영 데이터·장애 상황을 보장하지 않는다. DB 롤백이 이미 삭제된 원격 파일을 복구하는 것은 아니며, 원격 삭제는 재시도 가능한 멱등 처리에 의존한다.
